# Dependencies the Spark EXECUTORS need — deliberately not the full runtime set.
#
# Executors run the Turtle-parsing UDF (rdflib) and Arrow-backed serialization; the
# heavy machinery — torch, torch-geometric and their bundled CUDA libraries — is used
# only on the DRIVER (HeteroData assembly, torch.save), as requirements.txt states.
#
# This matters more than it looks. bin/package_venv.sh ships this environment to every
# executor, and a full venv is ~3.2 GB (nvidia 2.9 G + torch 0.9 G + triton 0.65 G).
# On a unified-memory GPU (where "GPU memory" IS host RAM), unpacking that on each
# executor floods the page cache, host free memory collapses, and RAPIDS then computes
# a GPU pool too small to satisfy its own floor and kills the executor -- which Spark
# relaunches, which unpacks 3.2 GB again. The job never progresses.
#
# Keep this list to what executors actually import.
#
# pyoxigraph parses the Turtle; rdflib is still here and still required, because
# it decides how a literal is spelled (its lexical->Python table) and it owns the
# blank-node relabelling. See turtle_to_rows in spark_jobs/build_graph.py. The
# wheel is 7.7 MB, which is nothing against the 3.2 GB this file exists to avoid.
pyoxigraph>=0.4.0,<0.6.0
rdflib>=6.0.0,<8.0.0
pandas>=1.0.5
pyarrow>=4.0.0

# setuptools is here for `distutils`, which it restores through the
# distutils-precedence.pth shim it installs.
#
# Python 3.12 removed distutils from the stdlib, and `python -m venv` on 3.12 no
# longer installs setuptools, so a venv built from this file has neither. Spark
# 3.5.3 still does `from distutils.version import LooseVersion` inside
# pyspark.sql.pandas.types.to_arrow_type, which every Arrow-batch UDF path calls
# on the executor -- so mapInArrow raises ModuleNotFoundError on the first task
# and the stage dies four retries later.
#
# It cost a cluster run on 2026-09-06 and is invisible locally: the DRIVER venv
# has setuptools, so the unit suite (including the Spark end-to-end parse test)
# passes while every executor fails. When a change touches what executors
# import, the packaged venv is a separate environment and has to be repackaged
# with bin/package_venv.sh.
setuptools>=68.0.0
